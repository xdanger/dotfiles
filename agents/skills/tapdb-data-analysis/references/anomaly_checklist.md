# 异常检测清单 (anomaly_checklist.md)

作为 Reviewer（审查者）在执行趋势与异常分析（场景 B）时，你必须逐条对照此清单，打钩确认，确保不会遗漏常见的业务影响因素：

- [ ] **步骤 1：周期性检查**：该时间段是否包含周末或公共节假日？（游戏 DAU 和收入周末往往会升高，属于正常周期性波动，而非突发异常）。
- [ ] **步骤 2：版本更新与活动影响**：
  - [ ] 查询 `version_distri` 或 activeDevices 是否有新版本冲高？
  - [ ] 对应的日流水是否有“尖峰”？该异常是否与版本发布或限时活动开启有关？
- [ ] **步骤 3：获取来源检查 (渠道与买量)**：如果新增(DAU/WAU)产生异常，进一步查询 `source` 分组，看是否是特定渠道（如 App Store、Google Play、某广告媒体）带来了一次性激增或断崖下跌。
- [ ] **步骤 4：核心买量成本检查**：查询 `cost`（或 `ad_data`），核对该时期的 CPI/CPA 或广告总消耗是否有大幅变化，排除因买量暂停导致的自然数据下滑。
- [ ] **步骤 5：数据延迟或漏报确认**：最后一天的数据是否异常偏低？（由于时差或数据上报延迟，通常不要将今天的未完整数据作为异常结论）。

在给出最终异常分析报告前，请在你的思考/草稿中明确回答上述问题。
